# 旧 MAKOTO の経緯と引き継ぐ資産

作り直し（makoto2）の前提となる、旧実装 [pooza/makoto](https://github.com/pooza/makoto) の経緯・停止理由・残っているデータ。**コードは引き継がないが、台詞コーパスは引き継ぐ価値がある。**

## 経緯

- 旧実装は長期間メンテされていなかった（最終コミット 2024-11-10）
- **2026-06-24 に全停止**（`makoto_enable=NO`）。同居していた本番サーバー（lbock）で**孤児プロセスが 11 日分たまり swap を約 800MB 占有**しており、キュアスタ！の投稿レイテンシ劣化の一因になっていた
- 以後ずっと停止したまま。アカウント [@makoto](https://precure.ml/@makoto) は 44,161 投稿・最終投稿 2026-06-24 で凍結状態
- **2026-07-29 夜に lbock が DNS ごと消えた**（サーバー移行で退役）。lbock 上にしか無かった実行時設定（`.env` 等）はもう取れない
- 旧リポジトリは 2026-07 にアーカイブ済み

## データはバックアップサーバーにだけ残っている

lbock 本体は消えたが、社内バックアップサーバー上の rsync バックアップが生きている。

| ファイル | 中身 |

| `makoto_2026-02-13.sql.zst`（39KB） | **唯一の DB スナップショット** |

**具体的な所在・取り出し手順は [pooza/chubo2](https://github.com/pooza/chubo2)（private）側を参照する**（このリポジトリは public のため書かない）。ファイル所有者・パーミッションの都合でバックアップサーバー上での昇格が必要。

⚠ **スナップショットは 2026-02-13 で止まっている**（停止した 06-24 の 4 ヶ月前）。lbock は writersbase-tools を使っておらず Google Drive バックアップにも含まれていないため、**それ以降の変更は取得できない**。

### 取り出し済み（2026-07-30）

ダンプはローカルの `var/corpus/` に取得済みで、[tools/pgdump_to_json.py](../tools/pgdump_to_json.py) でテーブルごとの JSON に落としてある。**`psql` を必要とせず、COPY ブロックを直接読む**ので、データストアが決まる前でも扱える。

```sh
python3 tools/pgdump_to_json.py var/corpus/makoto_2026-02-13.sql var/corpus
```

⚠ **`var/` はコミットしない**（`.gitignore` 済み）。このリポジトリは public で、コーパスには**第三者の著作物である台詞**と、`account` 393 件の**アカウント情報**が含まれる。取り出し元の所在と手順は `pooza/chubo2`（private）側を参照。

## 引き継ぐ資産: 台詞コーパス（quote + message ≒ 1,340 行）

**人手のメタ情報が付いており、そのまま新機能に対応する。** ここが作り直しでも引き継ぐ価値のある唯一の資産。

### quote（956 件）

スキーマは `quote(series_id, form_id, episode, emotion, exclude, exclude_respond, priority, body, remark)`。**「応答に使ってよいか」「優先度」「変身前後どちらの口調か」が既に人手で付いている。**

| 区分 | 件数 |
| --- | --- |
| **応答に使える台詞**（`exclude=f` かつ `exclude_respond=f`） | **561**（剣崎真琴 395 / キュアソード 165） |
| 投稿だけに使う（応答不可） | 289 |
| 完全に封印 | 106 |
| 話数（`episode`）が入っているもの | 871 |

- `form` = キュアソード / 剣崎真琴 / ちびキュアソード ＝ **変身前後で口調が分けてある**＝ペルソナ切替に直結する。応答可 561 件の内訳は剣崎真琴 395 / キュアソード 165 / **ちびキュアソード 1**
- 出典は `series` 7 作（ドキドキ!プリキュアが 870 件で主）
- `priority` は 1〜5 に分布する（既定の 3 が 475 件、1 が 167 / 2 が 158 / 4 が 139 / 5 が 17）。**抽選の重みとしてそのまま使える**
- `emotion` は 956 件中 25 件が `bad` で残りは null。**未使用ではなく、旧実装の好感度モデルの一部**（下記）

### message（388 件）

`type` が**絞り込んだ 4 機能とほぼ一対一に対応している**。

| type | 件数 | 対応する機能 | 原稿として使えるか（2026-08-05・#12 で実測） |
| --- | --- | --- | --- |
| `morning` | **237** | 朝挨拶 | ✅ 使う |
| `template` | 109 | 汎用テンプレート | ❌ **全 109 件が `%s` を含む** |
| `birthday` | **23** | バースデーライブ | ⚠ **19 件だけ**（季節指定を持つ 4 件は中身が秋の朝挨拶＝誤分類） |
| `calling` | 13 | 呼びかけ | ❌ **全 13 件が `%s` を含む** |
| `holiday` | 6 | 祝日 | ✅ 使う |

**`message` は `month` / `day` 列を持つ**＝「特定の日は前もって用意した原稿で上書きする」は旧実装で既に設計済み。

#### ⚠⚠ `template` と `calling` の 122 件は原稿ではない（#12 で実測）

**両方とも全件が `%s` を含む穴埋めテンプレート。**⚠ **そのまま投稿すると `%s` が出る。**`template` は `feature`（`一般` 59 / `人名` 39 / `地域` 11）と対応しており、未実装だった**キーワード学習**の素材。`calling` は相手の名前を差し込む**呼びかけ**で、チャットボット（#18）が使うならそちら。

⚠ **原稿の上書き機構（#12）の許可リストに入れてはいけない。**逆に `morning` / `birthday` / `holiday` の 266 件には `%s` が 1 件も無い。

#### ⚠ `birthday` 23 件のうち 4 件は誕生日の原稿ではない（#12 で実測）

**季節指定（`{"season": [9,10]}` / `[8,9]`）を持つ 4 件は、中身が紅葉・葡萄・梨のダジャレ**＝秋の朝挨拶。⚠ **11/4 に出すと季節外れになる。**上書き機構は「季節指定を持たない `birthday`」＝ **19 件**だけを誕生日に使う。

⚠ **残る 19 件も、歌や自己紹介を語るのは前半 8 件ほどで、後半（ギターの練習・きのこが嫌い・焼肉・プリン・流れ星）は普通の雑談。**「誕生日らしい原稿」を確実に出したいなら、**11/4 用の原稿を年指定（`year`）で書き下ろす**（→ #13）。⚠ 年指定は 19 件より優先される。

#### 日付の指定は 2 系統ある（実データで確認）

⚠ **`month` / `day` を使っているのは `holiday` の 6 件だけ。`birthday` 23 件は日付を持たない。**「11/4 に出す」判定は日付列ではなく **`type` の側**で行われていた。原稿の上書き機構（#12）を作るときの前提になる。

`month`/`day` を持つ 6 件は元日・プリキュアの日（2/1）・バレンタイン・エイプリルフール・**キュアスタ！の誕生日（4/23）**・クリスマスイブ。

もう 1 系統が **`data` 列（json）の `season`** で、**月の配列**を持つ。

| type | `data` あり | 例 |
| --- | --- | --- |
| `morning` | 82 / 237 | `{"season": [6,7,8]}` |
| `birthday` | 4 / 23 | `{"season": [9,10]}` |

つまり旧実装の原稿選択は「**特定日（month/day）→ 季節（data.season）→ 無指定**」の 3 段構えだった。makoto2 でも**季節フィルタは引き継ぐ価値がある**（朝挨拶 237 件を通年で回すと季節外れが出る）。

✅ **makoto2 では「その年のその日 → 毎年のその日 → 記念日 → 季節 → 無指定」の 5 段にした**（#12・`MessageSelector`）。⚠ **年（`year` 列）と記念日（`/message/anniversary`）が新しく足した段**で、前者は台本（#13 / #14）、後者は日付を持たない `birthday` のためにある。

#### `feature` 列はキーワード機能の名残

`feature` は 388 件中 109 件に入っている（`一般` 59 / `人名` 39 / `地域` 11）。`keyword` / `past_keyword` テーブルが 0 件であることと合わせて、**未実装だった「キーワード学習」の作りかけ**とみられる。絞り込んだ 4 機能には不要。

### 旧実装の好感度モデル（`account.favorability` + `emotion=bad`）— 引き継がない

旧 MAKOTO はアカウントごとに好感度を持ち、**簡単な感情モデル**で応答を切り替えていた。

- **挨拶などで上がり、卑語で下がる**
- `account(id, acct, favorability, nickname)` の `favorability` がその値。実データは 393 件で **-17 〜 7,416** に分布し、0 が 87 件・負の値は 18 件
- **しきい値を下回ると `emotion='bad'` の台詞だけを返すようになる**。`bad` の 25 件は**本編で真琴が怒っている台詞**（キュアソード 9 / 剣崎真琴 16。うち 9 件は `exclude_respond` が立っていて投稿専用）

つまり `emotion=bad` は「卑語を投げてくる相手に怒って返す」ための区分であって、未使用の列ではない。

**makoto2 では引き継がない**（2026-07-30 に確認）。ただし**卑語への応答をどうするかという課題自体は残る**ので、チャットボット（#18）では別の形で扱う。LLM 方式ではプロンプト側の制約として書くほうが素直で、好感度という状態をアカウント単位で永続化する必要は薄い。

### `fairy`（62 件）— 語尾の辞書

妖精名・`human_name`（変身する人間の名前）・`suffix`（語尾）を持つ。`アロマ`→`ロマ`、`キャンディ`→`クル`、`キラリン`→`キラ星 シエル`/`キラ` など。

**makoto2 では使わない**（2026-07-31 決定）。**語尾を管理するという要件自体が無くなった**ため。旧実装は妖精の語尾を辞書で持って文字列を加工していたが、makoto2 は台詞コーパスを LLM の素材として使う方式なので、語尾を機械的に付け替える処理が要らない。

なお、仮に必要になっても **makoto2 に抱え込まない。**妖精はプリキュア作品の情報なので、正本は [cure-api](https://github.com/pooza/cure-api) 側（`series` と同じ理屈 → [CLAUDE.md](CLAUDE.md)）。

### 使い方を変える

⚠ **旧実装は台詞をそのまま返していた**とみられ、文脈を無視して台詞を貼った投稿が実際にあった。これが「キャラのぶれ」の正体である可能性が高い。

**makoto2 では LLM の few-shot / RAG 素材として使う。** 561 件はファインチューニングには少ないが、プロンプト同梱には十分な量。

## 引き継いだ既知ドリフト（nginx `/makoto`）→ ✅ 解消済み（2026-07-31）

nginx の `/makoto` ロケーションは Mastodon フォークの vhost 側にあるため、**キュアスタ！のサーバー移行（lbock → gomander、2026-07-28）でそのまま引き継がれていた**。

- 配置はデルムリン丼とキュアスタ！の 2 台（各サーバーの vhost 設定）。他の 2 台には無かった
- バックエンドの 3011 は誰も listen していないので**実害は 502 のみ**
- `/makoto/sidekiq` の ACL が `/mulukhiya/sidekiq` と食い違ったまま — **退役したホストの旧プレフィクスを許可しており、モロヘイヤ側が持つ現行の許可元が入っていなかった**（具体的な CIDR は chubo2 側を参照）

**この location は踏襲しない。** `/makoto` は旧実装の**管理コンソール**で、パスを知っていたのは運用者ひとりだった。makoto2 に引き継ぐべき利用者も用途も無く、残しても 502 と ACL の食い違いを抱え続けるだけだった。

✅ **2026-07-31 に 2 台とも削除・反映済み**（`pooza/chubo2#99` クローズ）。`location ^~ /makoto/sidekiq` と `location ^~ /makoto` の計 9 行を削除し、`nginx -t` 通過後に reload。**両ホストとも 502 → 404 になったことを確認済み。**

**makoto2 では管理コンソールそのものを作らない。** 運用操作は CLI で行う（→ [CLAUDE.md](CLAUDE.md) の「管理操作は CLI で行う」）。旧実装で Issue が立っていた「WebUI からの辞書更新」も、WebUI ではなく CLI として作る。
