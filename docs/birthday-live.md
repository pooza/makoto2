# 11/4 バースデーライブ

makoto2 の**実質的な締め切り**であり、作り直しのゴール。

## 位置づけ

**11/4 は MAKOTO の誕生日という設定**（モデルの剣崎真琴＝キュアソードと同じ日）。以前は「バースデーライブ」と銘打ち、少しストーリー性を持たせて頻度を上げて投稿させていた。**どうにかこれはやらせたい**という要件。

- **11/1 から予告を始める**＝機能的な締め切りは 11/4 ではなく **11/1**
- **2026-11-04 は水曜、11/1 は日曜**（ニチアサ実況の日＝サーバーが最も賑わう日）

## ⚠⚠ 発想の出どころは真琴ではなく宮本佳那子さん

**ライブ名（SONGBIRD PARTY）は真琴の側から来ているが、「バースデーライブをやる」という発想そのものは声優の側から来ている。**⚠ **この 2 つは出どころが違う。**

- **宮本佳那子さんは毎年のバースデーライブにとても力を入れている**
- ⚠ **旧実装でこの機能を作った直前の回が入魂のもので、「なんとか再現できないか」と考えたことが実装の動機**
- **その回の構成**: ⚠ **昼夜の前後編に分かれ、キャリアに応じて順に歌っていく**。⚠⚠ **夜の部がキュアソードの歌を含むパート**
- 参照: <https://pf.korako.me/post/12139>（⚠ 認証が要るのか、ツールからは 403 で読めない。内容はオーナーの記憶による）

⚠ **これは [makoto-persona.md](makoto-persona.md) の「歌は声優と重ねてよい領域」の実例そのもの。**歌に関わる部分だから、声優側の発想をそのまま持ち込んでも破綻しない。⚠ **同じことを出自や家族でやると壊れる。**

### ⚠ 元ネタの構成が、そのまま実装の指針になる

| 元の構成 | makoto2 での対応 |
| --- | --- |
| **昼夜の前後編** | **12:00 開始 / 20:00 終了の 8 時間枠**が、通しで昼夜にまたがっている |
| ⚠ **キャリアに応じて順に歌う** | ⚠ **`releaseDate` で並べれば再現できる。**ライブ用 234 曲は **2007〜2024** に分布（2013 が 87 曲でピーク）。**データは既にある** |
| ⚠⚠ **夜の部がキュアソードのパート** | ⚠ **キュアソード関連曲を後半に寄せる。**下記「こころをこめて を終了告知の直前に」と**同じ方向を指している** |

⚠ **「キャリア順」は抽選ではなく整列。**#11（`kind` による重み付け抽選）とは別の軸なので、**ライブは抽選ではなくセットリストとして組む**ことになる。設計時に混同しない。

## 2024 年の台本（時刻は JST）

| 時刻 | 投稿 |
| --- | --- |
| 12:00 | 「剣崎真琴バースデーライブ **SONGBIRD PARTY 2024** スタートです！ **20:00 まで歌い続けます**。聴きたくない方はミュートしてくださいね」 |
| 〜20:00 | 曲を歌い続ける |
| 20:00 | 「これでおしまいです。最後まで聴いてくれてありがとう。**また来年、会いに来てね**」 |

**開始と終了の告知で挟んだ 8 時間の枠**という構造。前日（11/3）も投稿を増量して助走をつけている。

⚠ **開始の告知は「聴きたくない方はミュートしてください」＝退出路を提示する形**になっている。**参加を強いない**という方針（→ [CLAUDE.md](CLAUDE.md)）と、真琴が映画のプロローグで観客に呼びかける register（→ [makoto-persona.md](makoto-persona.md)）の両方に合っている。**2026 もこの形を踏襲する。**

### ⚠ ソロアルバムはシリーズ史上唯一

**普段用 4,305 曲・400 アルバムを走査して、単一アーティスト名義のキャラクターアルバムはこの 1 枚のみ**（悉皆調査ではないが十分な傍証）。

⚠ **「8 曲が同じアルバムに入っている」というデータの観察よりも、こちらのほうが強い根拠になる。**プリキュアシリーズで単独のキャラクターアルバムを持っているのが剣崎真琴だけである、という事実が、**歌手であることをペルソナの核に据える裏づけになる**（→ [makoto-persona.md](makoto-persona.md)）。

## ⚠ 「こころをこめて」の重みは三層。うち 2 つは口に出せない

| 層 | 中身 | MAKOTO が語れるか |
| --- | --- | --- |
| **劇中** | 40 話で、友人としてのレジーナに贈った歌 | ⚠ **一部のみ。**レジーナ＝王女の転生は明かせない |
| **メタ** | ⚠ **アルバム（2013-05-29）が先で、11 月の本編が後から呼び戻した。**当時「キャラソンは本編で使われるとは限らない」が前提だったため、ファン側の事件でもあった | ⚠ **語れない。**真琴として喋る以上、ファン視点を持てない |
| **ライブ** | 唯一のソロアルバムの最終曲 | ✅ **曲そのものは出せる** |

### ⚠ 提案: 終了告知（20:00）の直前に置く

**アルバムの曲順とライブの構造が一致する。**由来を一言も説明せずに、**形式だけで重みが乗る。**

- 12:00 の開始告知の近くに **1 曲目 `〜SONGBIRD〜`**（ライブ名そのもの）
- 20:00 の終了告知の直前に **8 曲目 `こころをこめて`**

⚠ **語れない 2 層を、曲順という語らない手段で回収する。**#13 の台本で採否を決める。

## ⚠ 歌の核心は「投稿専用」の台詞にある

**ライブは応答ではなく投稿なので、`exclude_respond`（投稿専用）の台詞がそのまま使える。**

| 抽出条件 | 件数 | 区分 |
| --- | --- | --- |
| `priority` 5 かつ「歌」を含む | 5（ep6 87字 / ep7 89字 / ep24 76字 / **ep40 25字** / ep49 109字） | ⚠ **ep40 以外すべて投稿専用** |
| 「プロ」を含む | 2（ep5 78字 / ep24 82字） | ⚠ **両方とも投稿専用** |

⚠ **応答可の平均 12.4 字とはまったく別の register**（宣言・演説）。**8 時間を埋める語りの素材は、濃いところに実在している。**

⚠ **[makoto-persona.md](makoto-persona.md) は歌の素材を「26 件（応答可 8）」と応答可ベースで評価しているが、ライブに関してはこの評価は当たらない。核心は応答可の外にある。**

## 必要なもの

- **曲データ** — 旧 DB の `track` テーブルは 0 件で歌う中身が残っていない。iTunes Search API から自動収集する方式を実証済み（→ [track-corpus.md](track-corpus.md)）。**ライブ用 234 曲のうち vocal が 194 曲**

  ⚠⚠ **訂正（2026-08-02）: 「8 時間を重複なしで回せる量」は成り立たない。**

  | | 数 |
  | --- | --- |
  | vocal（行数） | 194 |
  | ⚠ **vocal（曲名ユニーク）** | ⚠⚠ **144** |

  **50 行は名義違い・盤違いの同一曲**（`しまうまグルグル` 5 行・`手と手つないでハートもリンク!!` 4 行など、33 曲が重複）。⚠ **`trackId` は 234 件すべてユニークなので、id だけで重複を排除できない。曲名で寄せる必要がある。**

  ⚠⚠ **さらに枠が埋まらない。**ライブ当日は **2〜3 分間隔で投稿する**前提（→ [CLAUDE.md](CLAUDE.md)）なので、**480 分の枠には 160〜240 投稿が要る**。⚠ **1 投稿 1 曲なら 144 曲では足りない。**

  **取りうる手**: ①普段用 4,305 曲（vocal 1,479）から補う ②投稿間隔を広げる ③曲以外の投稿（MC 相当・告知・呼びかけ）を挟む ④重複を許す。⚠ **③は元ネタの構成（昼夜の前後編）とも相性がよい。**#13 で決める
- **投稿スケジューラ** — 12:00 開始 / 20:00 終了の固定枠と、その間の配信ペース
- **原稿の上書き** — 開始・終了の告知は前もって用意した原稿を使う。旧 `message` テーブルの `birthday` type **23 件**がこの用途（→ [makoto-legacy.md](makoto-legacy.md)）

  ⚠⚠ **実装前提の訂正（2026-08-02）: `birthday` 23 行の `month` / `day` / `feature` は全行 NULL。****日付で引ける作りになっていない。**`data` に値があるのも 4 行だけで、中身は `{"season": [9,10]}` / `{"season": [8,9]}`＝**季節指定であって誕生日ではない**。

  したがって **11/4 という日付をどこから与えるかは #12 / #13 で新しく決める必要がある**。旧 DB の列をそのまま使う前提で設計しないこと。

## 判断が要る論点

- ⚠ **ライブ中に MAKOTO を怒らせるか**（#13 / #20）— ライブは文字通りステージで、**本編の真琴なら怒る場面**（怒りは相手ではなく行為に向く → [makoto-persona.md](makoto-persona.md)）。2024 年の台本は**怒るのではなく退出路を示す**形で処理していた。コミュニティボットが利用者に怒るのは運用上危ないので**台本側に寄せる案を推す**が、キャラクターの筋としては割り切りになる。**#13 で決める**
