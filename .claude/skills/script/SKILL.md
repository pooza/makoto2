# 原稿を書き足す

⚠ **この手順の正本はこのファイル**（#540 で `docs/CLAUDE.md`「原稿を書き足すときの決まりごと」から運用の決まりを移した）。**踏んだ記録（11/4 の朝挨拶の割り方・#225 の進捗・実測の間隔）は docs に残してある。**
🔴 **`makoto-scripts` への PR を含むので明示呼び出しに限ってある。**

🔴 **このスキルが持つのは段取りだけ。書く中身の正本は動かさない:**

| 何を | 正本 |
| --- | --- |
| 人物・語ってよい範囲・語彙・register | [docs/makoto-persona.md](../../../docs/makoto-persona.md) |
| 朝挨拶の形（2 行・42 字前後・敬体が基底・話題の比率・ダジャレ 15 件に 1 件） | [docs/makoto-legacy.md](../../../docs/makoto-legacy.md)「朝挨拶原稿の仕様」 |
| ファイルごとの決まり（前置きで言わないこと・種類別の注意） | `makoto-scripts` の各 YAML の冒頭のコメント |
| 形式・slug・取り込み・表記（「私」「こころをこめて」） | `makoto-scripts` の README |

⚠ **書く前に、該当する正本を読み直す**（決まりは後から足される。2026-09-28 の上下のニュアンス、2026-10-20 の一人称）。

## 1. 決める（ユーザー）

- **どの type に何本か。**🔴 **本数が一周の長さ**（朝挨拶の通年 ＝ 一周の日数・前置きは 1 日 3 本なので 90 本 ＝ 30 日）。⚠ 種類別の前置きは束ごとに下限を置く
- ⚠ 季節つきの朝挨拶は 12 か月すべて 16 本以上で底が揃っている（2026-09-03）。**足すなら通年へ回す**のが基本

## 2. ブランチを切る

```sh
git -C ../makoto-scripts fetch origin
git -C ../makoto-scripts switch -c feat/<要旨> origin/main   # ⚠ fetch せずに切ると衝突する
```

## 3. 書く

- 🔴 **`slug` が取り込みの鍵**（id は使えない）。⚠ 続き番号で付け、既存と重ねない。台本の途中に差し込むときは `live-mc-04a` のように前後の間に並ぶ名前にする（→ README「形式」）
- 🔴 **`date:` は `MM-DD`（毎年 ＝ 段 2）と `YYYY-MM-DD`（その年だけ ＝ 段 1）の 2 通り**（`ScriptImporter.parse_date`・段 1 が段 2 に勝つ）。⚠⚠ **その年にしか成り立たないことは `YYYY-MM-DD` に書く** — `MM-DD` に書くと翌年から嘘になる（#234）
- 🔴 **動く祝日を「今日」と言わない**（2026-09-03・Codex の P2）。⚠⚠ `season:` の原稿はその月のどの日にも出るので、「今日は敬老の日ですね」は 9 月の大半で偽になる。段 2 は月日固定なので曜日相対（9 月第 3 月曜）を指せない — **日を名指ししない形に直す**（「九月は敬老の日のある月ですね」）。⚠ ハロウィンも同じ
- ⚠ **新しく書くものは 1 原稿 1 月**（多月指定は年に複数回出る・#225）。旧データの 80 本は多月のまま書き換えない
- ⚠ **通年に季節の語と、古びる固有名詞を入れない**（#60 の「捨ててよい 10 件」がまさに後者で古びた）
- ⚠ **1 つの type は 1 つのファイルに収める**（`--prune` はファイルに出てくる type だけを消すので、分けると片方を入れたときにもう片方が消える）
- ⚠ **`drafts/` は取り込まれない**（直下の YAML しか読まない）。誕生日の原稿の段取りは README「誕生日の原稿は、使ったら次を書く」
- ⚠ **作り手に上下のニュアンスを付けない**（後ろ・陰・裏方・支える・主役でない）。真琴は演じる側でもある

## 4. 検査する

```sh
.claude/skills/script/scripts/check.sh ../makoto-scripts   # 読むだけ・比べる版は origin/main
```

- ✗（slug の欠け・重なり、type がファイルをまたぐ、多月指定、`date:` の形）は直してから先へ
- ⚠ は**足した行だけ**に出る（語で拾える決まり: 一人称・「こころをこめて」・問いで終わる・上下の語・前置きの禁句・時刻と季節）。**人が読んで決める**（例外がある: 真琴自身が歌う側だと言う行は「歌」を使ってよい）
- 🔴 **語で拾えないものの方が多い**（曲の性格を言う・本編に無いことを語る・寡黙さ）。⚠ **✗ 0・⚠ 0 は「決まりを満たした」ではない** — 正本を横に置いて 1 本ずつ読む

## 5. 測る（手元の DB）

```sh
bin/makoto message import ../makoto-scripts --prune   # 手元の DB を正本に揃える（何度流してもよい）
bin/makoto morning slot                               # 通年の本数 ＝ 一周の日数・季節の月ごとの本数
bin/makoto song slot                                  # 前置きの本数と、同じ前置きが戻る最短の間隔
bin/makoto morning preview --days=14                  # 足した原稿が出る日を見る
bin/makoto song preview --days=7
```

- ⚠ **取り込みの前に、手元の DB が正本より古いことがある**（2026-11-06 は 164 本古かった）。測る前に必ず取り込む
- ⚠ 書き足しに `message export` → `corpus import` は要らない（あれは 2026-09-01 の移送の段取り → docs「朝挨拶の原稿の正本は `makoto-scripts`」）
- ⚠ **数字は README に書かない**（手で足すたびに古くなる → README は数え方だけを置いている）。⚠ 2026-09 の手順にあった「README の 3 つの数字を同じ PR で直す」は、数え方に置き換えたので要らない

## 6. PR に出す

```sh
git -C ../makoto-scripts push -u origin feat/<要旨>
gh pr create --repo pooza/makoto-scripts --base main --title 'feat: <要旨> (pooza/makoto2#n)' --body-file <本文>
```

- 本文に入れるもの: 何を何本・`check.sh` の本数の差（`（a → b）`）・`slot` の一周の変化・⚠ の扱い（直した／残した理由）
- 🔴 **Codex は通さない。オーナーのレビューだけでマージする**（2026-09-28）。⚠ 出す側が先に 4. を済ませておく
- 🔴 **makoto-scripts は private、makoto2 は public。**原稿の本文を makoto2 の Issue・PR・docs・コミットに書かない（本数と slug までにする）

## 7. マージの後

- ⚠⚠ **マージしても実機には届かない。**レシピ（chubo2 の makoto2）が `makoto-scripts` を引いて `message import --prune` を流したときに入る → [deploy スキル](../deploy/SKILL.md)
- ⚠ 実機で当てるなら `bin/makoto morning slot` / `song slot` を `bydo` で（手元と本数が一致すること）
- 書き足しの元になった makoto2 の Issue にコメントする（本数と一周の変化・PR の番号）
