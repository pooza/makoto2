# リリース前レビュー

⚠ **この手順の正本はこのファイル**（#536 で `docs/CLAUDE.md`「リリース前レビュー」から移した）。**各版のレビューの記録（何が出て、どこへ送ったか）は `docs/CLAUDE.md` の同名の節に残す。**
⚠ **外へ書く step を含む**（送る指摘の起票）ので明示呼び出しに限ってある。

**単一のセキュリティレビューだけでは実用上の問題が取りこぼされる**（モロヘイヤ・capsicum の両方で実証済み）。5 観点を独立に走らせて指摘を合流させる。

## 1. 範囲を決める

```sh
git fetch origin
git describe --tags --abbrev=0 origin/main     # 前のリリース
git diff --stat <前のタグ>..origin/develop
```

🔴 **レビューするのはこのリリースの差分**（前の版で済ませた結果を流用しない）。

## 2. 5 観点を並列に走らせる

Agent ツールで **1 観点 1 サブエージェント・同じ応答の中で 5 本**。各エージェントには「範囲（`<前のタグ>..origin/develop`）・観点・下の焦点・`docs/CLAUDE.md` の該当する設計の節を読むこと・赤 / 黄 / 緑の定義・各指摘に起きる条件（入力と状態）を付けること」を渡す。⚠ 自分の見立ては渡さない（独立に読ませる）。

| 観点 | 焦点 |
| --- | --- |
| セキュリティ | `/security-review`。トークン・API キーの取り扱い、シークレットの scrub（ログ・Sentry）、入力検証、SSRF、原稿の書き出し先（public のリポジトリへ漏らさない） |
| 外部 API 契約 | Mastodon API（モロヘイヤ経由・冪等キー・429）、iTunes Search API、cure-api、`ginseng-*` の interface、LLM プロバイダ |
| 並行性・ライフサイクル | 常駐プロセス・スケジューラ（`Scheduler` / `PostingJob#claim`）・pid と孤児・痕跡の書き込み・systemd の `Restart=always`・SQLite 接続 |
| エラー処理・観測性 | 例外の分類、fail-open / fail-closed の向き、`makoto status` と `/healthz` の判定、`rehearsal report` の赤、ログの個人情報 |
| コーディングスタイル・規約整合性 | rubocop、`rake config:lint`、設定のスラッシュ記法、2 スペースの論理インデント、表記規約（`docs/CLAUDE.md`「コーディング規約」） |

⚠ **Codex（`chatgpt-codex-connector[bot]`）はリリース PR で走る**ので、そちらと重なる指摘は 1 つにまとめる（#38）。Codex の P2 は 1 巡だけ。

## 3. 分けて報告する

- **赤（必修）**: データ破損・セキュリティ・ユーザー可視の機能不全 → **本リリースで直す**
- **黄（余力があれば）**: 単一の edge case、観測性のギャップ
- **緑（送り）**: 将来の構造改善

報告は日本語の一覧で、各指摘に**「直さないと何が起きるか・誰に・どのくらいの頻度で」を 1 行**付ける。🔴 **黄・緑の行き先はユーザーが指摘ごとに決める**（自分で起票しない）:

| 行き先 | 使うとき |
| --- | --- |
| この版で直す | 自分が入れた穴で、その場で直せる規模（⚠ ステージング検証より前に） |
| `0.x.1` の箱（無ければ作る） | 送るもの。⚠ 性格の合う次の箱があるならそちらでよい。🔴 `.1` を閉じた後に送るものは `0.x.2` |
| 上流の Issue にコメント | 原因が `ginseng-*` 側にあるもの |
| 記録のみ | 判断が付かないもの（`docs/CLAUDE.md` のその版のレビューの節に 1 行） |

- 🔴 **機能が全台 OFF ＝ ライブ露出ゼロなら、真の赤でも非ブロック化して受け皿 Issue に送ってよい**
- ⚠⚠ **「見つけたものは全部直す」にしない** — 直した差分がまたレビューの対象になり、リリースが収束しない
- 🔴 **赤を直したら、ステージング検証（release 4.）をやり直す**。合否を出す道具そのもの（`rehearsal report` など）を直したときも同じ

## 4. 記録する

`docs/CLAUDE.md`「リリース前レビュー」に `#### ✅ vX.Y.Z のリリース前レビュー（日付・赤 n / 黄 n / 緑 n）` の節を足し、何をどこへ送ったかを書く。起票した Issue にはマイルストーンを必ず付ける（付けたら箱の表と説明文の重みも直す）。
