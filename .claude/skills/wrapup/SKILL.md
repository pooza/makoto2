# ラップアップとモンキーテスト

⚠ **この手順の正本はこのファイル**（#537 で `docs/CLAUDE.md` の「ラップアップ時は…分類する」「タスクの正本は Issue」「モンキーテストは実機で当てる」から移した）。**踏んだ記録（v0.3.0 の 28 件・#41 で当たらなかった分岐）は docs に残してある。**
🔴 **Issue へのコメント・クローズを含むので明示呼び出しに限ってある。**閉じる・移すはユーザーに確かめてから。

🔴 **ラップアップはセッションを締めることではない。**締めるのは常にユーザー。⚠ 終わっても自分から「おつかれさまでした」で締めない（応答は開いたままにする）。⚠ 逆に「次は〜やりましょう。おつかれさま」は**次回へのポインタと締め**であって着手の指示ではない — 次のボリュームを要約するところで止まる。

## 1. 着地したものを並べる

```sh
.claude/skills/wrapup/scripts/landed.sh [YYYY-MM-DD]   # 既定は今日。読むだけ
```

⚠ develop 宛の PR では `Closes #n` が効かないので、Issue は open のまま残っている。⚠ マイルストーンの無い Issue が出てきたら、それも報告する（Issue には必ず箱を付ける）。

## 2. 分ける

| 分類 | 例 | 扱い |
| --- | --- | --- |
| **モンキーテストができない** | 内部最適化・純粋なリファクタ・docs だけ | 🔴 **即クローズ**（何を入れたかを 1 行コメントしてから） |
| **できる** | 投稿・下見・CLI・設定の検査・異常系 | 3. で当てる。当てられないなら **open のまま観点のメモ**を付ける |
| **リリースで使って初めて閉じる** | 手順・スキル（完了条件が「次のリリースで使った」） | open のまま。いつ閉じるかを書く |

## 3. 実機で当てる

- 🔴 **まず実機がその版で動いているかを見る**（`.claude/skills/sync/scripts/hosts.sh bydo`）。動いていなければ、何日待っても結果は出ない — 当てるには [deploy スキル](../deploy/SKILL.md) で `bydo` に当てる（ユーザーの指示で）
- ⚠ **「コードが入った」で閉じない。**出力を見る。⚠⚠ **異常系は作って踏ませる**（設定を壊して起動する・偽のサーバを立てる・pid ファイルを書き換える・原稿を消して時刻を騙す・下見を流しても行が増えないことを見る）
- ⚠ 下見（`bin/makoto live setlist` / `song preview` / `morning preview`）で足りるものは、投稿せずに当てる
- ⚠ 自分の測り方が誤報を出すことがある（`pgrep -f` が自分の ssh のコマンド行に当たる、など）。食い違ったら製品の側を疑う前に測り方を疑う
- ⚠ ステージング宛のテスト投稿は消さなくてよい（別のテストに支障が出るときだけ消す）

## 4. Issue に書く

🔴 **確かめたら、その Issue にコメントしてから閉じる。**会話の中だけに置かない。コメントに入れるもの:

- **観点**と、**実際の出力**（抜粋）
- 🔴 **実機で当てた条件と、テストに預けた条件を書き分ける。**⚠ 書き分けるときは「なぜ実機では当たらないか」まで書く（「時間」と書くと「待てば当たる」に読める — 条件が時刻で決まらないなら、そう書く）
- 撤収したもの（騙した時刻・壊した設定・偽のサーバ）を戻したこと
- ⚠ 確かめられなかったものは、確かめられなかったと書いて残す（または箱を移す。移したら箱の表と説明文の重みも直す）

## 5. 次回への手掛かり

- メモリの経過ログ（`project_makoto2-kickoff.md`）に、その日の着地と「次にやること」を足す（日付は YYYY-MM-DD）。⚠ 引き継ぎに要る知見は docs に書く（メモリはポインタ）
- 次のボリューム（箱に残る Issue・重み・依存）を要約して報告する。⚠ 着手の順を選ばせる問いまでは進まない
