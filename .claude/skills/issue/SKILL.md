# Issue を足す・箱を動かす

⚠ **この手順の正本はこのファイル**（#538 で `docs/CLAUDE.md`「Issue / マイルストーン運用」から手順の部分を移した）。**箱の決まり（名前は 2 桁・日付でしか閉じられないものは別の箱・`.1` / `.2` の箱・重みの目安）と踏んだ記録は docs に残してある。**
🔴 **起票・マイルストーンの書き換えを含むので明示呼び出しに限ってある。**

🔴 **同期 10.（[sync](../sync/SKILL.md)）で拾うずれは、ほぼ全部「Issue を足した・動かしたときに表と説明文を直していない」形**（2026-11-05 にも #526 で踏んだ）。同期は検出で、こちらは**書く時点で揃える**。⚠ **Issue を 1 件足したら、3. まで済ませて 1 回と数える。**

## 1. 決める（ユーザー）

- **箱**: どのマイルストーンか。⚠ **箱は版ではなく「その版の系列」**、性格で選ぶ（→ docs「Issue / マイルストーン運用」「バージョニング」）
  - 🔴 **日付でしか閉じられないものを開発の箱に入れない**（日付の箱へ）
  - ⚠ リリース前レビューで送る黄・緑は `0.x.1`（`.1` を閉じた後は `0.x.2`）。⚠ 性格の合う次の箱があるならそちら
  - ⚠ **箱なしも選べる**（「マイルストーン未設定の軽い課題は近接処理する」）。⚠ **スコープを決める ＝ 箱に入れること**（docs に書くだけでは決まっていない）
- **サイズ**: `size:S`（50 行未満・docs）＝ 1 / `size:M`（50〜200 行）＝ 3 / `size:L`（200 行超）＝ 8。⚠ **箱の目安は重み 20〜25**。超えるなら「なぜ送れないか」を説明文に書く（黙って破らない）
- ⚠ **「相談」は起票がゴール**（実装に進まない）。⚠ **原因が `ginseng-*` 側なら、上流の Issue として出す**（専任のエージェントがいる → docs「`ginseng-*` との往復」）

## 2. 起票する・移す

```sh
gh issue create --title '<種別>: <要旨>' --body-file <本文> --label size:S --milestone '0.9'
gh issue edit <n> --milestone '<移す先>'          # 移す（⚠ 箱から外すのは --remove-milestone）
```

- 題の頭は `fix:` / `feat:` / `docs:` / `chore:` / `設計検討:` など（既存の Issue に合わせる）
- 本文: **背景**・**完了条件**（何をしたら閉じるか）・関連（`#n`）・末尾に `🤖 Generated with [Claude Code](https://claude.com/claude-code)`
- 🔴 **日付は YYYY-MM-DD**（「来週」「11/4 の後」だけにしない）。🔴 **リポジトリは public** — ホストのアドレス・トークン・個人の連絡先を書かない
- ⚠ 元の Issue を送るときは、**受け皿を起票してから元を閉じる**（「閉じてから起票」は消える）

## 3. 揃える（足した箱・出した箱のすべてで）

```sh
.claude/skills/sync/scripts/milestones.sh                  # ① 実測（手で足し引きしない）
.claude/skills/issue/scripts/box.sh <箱> '<足す行>'         # ② 説明文の差分を見る
.claude/skills/issue/scripts/box.sh <箱> '<足す行>' --apply # ③ 説明文を書く
#   ④ docs/CLAUDE.md の箱の表の「重み」の欄を ① の実測に直す（PR で）
.claude/skills/sync/scripts/milestones.sh                  # ⑤ 実測 ＝ 表 ＝ 説明文、⚠ の印が無いこと
```

- 説明文に足す行の型（`{before}` / `{after}` は `box.sh` が埋める）:

  ```text
  ⚠ **YYYY-MM-DD に #n を追加**（`size:S`・**重み {before} → {after}**）— 要旨（判断した人）
  ⚠ **YYYY-MM-DD に #n を <元の箱> から受けた**（`size:S`・**重み {before} → {after}**）— 理由
  ✅ **YYYY-MM-DD に #n を <先の箱> へ移した**（**重み {before} → {after}**）— 理由
  ```

- 🔴 **移したら、出した箱と入れた箱の両方で ②〜⑤ を回す**
- ⚠ **docs の表は重みの欄だけ直せば足りる**（内容の欄に Issue を並べている箱は、その欄も）。⚠ 重みの欄に説明文が混ざったら表の列が崩れている（`milestones.sh` が「⚠ 列がずれている」と出す）
- ⚠ 記録に「実測」と書くのは ① を見た回だけ

## 4. 箱を作る

```sh
gh api repos/pooza/makoto2/milestones -f title='0.10' -f state=open -f description='<何を出す版か>（YYYY-MM-DD 新設・判断した人）'
```

- 🔴 **名前に末尾の `.0` を付けない**（`0.10` であって `0.10.0` ではない。`.1` / `.2` の箱だけ 3 桁）
- 説明文は「何を出す版か」から書く（⚠ 軸が無い箱は「残りが溜まる場所」になる → docs「`0.4` を性格で割った」）
- docs の箱の表に行を足す（箱の名前・内容・重みの 3 列）。⚠ 同期のスクリプト（`milestones.sh`）は箱の一覧を API から引くので、直すところは無い
- ⚠ 着手するときは最初にバージョンをバンプする（`config/application.yaml`）

## 5. 閉じる

- 着地した Issue を閉じるのは [wrapup](../wrapup/SKILL.md)、箱を空にして閉じるのは [release](../release/SKILL.md) の 10.
- 🔴 **確かめたら、Issue にコメントしてから閉じる**（会話に置かない）
